# Бета-тест: как получить APK и войти

## Демо-APK (без сервера) — для проверки экранов

* GitHub → **Actions** → **Android beta APK** → последний зелёный запуск → внизу
  **Artifacts** → `avatar-demo-apk` (zip, внутри `.apk`). Собирается сам при каждом
  push в `main`, `develop` или `claude/*`; вручную — кнопка **Run workflow**.
* Поставить на Android «из файла» (разрешить установку из неизвестных источников).
* Вход: любой номер `+7…`, **любой код, кроме `0000`** (`0000` — проверка ошибки).
* Данные выдуманные и живут только в памяти телефона; после перезапуска всё сброшено.
  В правом верхнем углу лента **«ДЕМО»** — с боевым приложением не спутать.
* Меню-«жук» в ленте переключает состояния: загрузка / пусто / ошибка.

Локально то же самое: `flutter build apk --profile --dart-define=DEMO_MODE=true`.

## Staging-APK (настоящий тестовый сервер)

Появляется в тех же Artifacts как `avatar-staging-apk`, когда в репозитории заданы
секреты `STAGING_SUPABASE_URL` и `STAGING_SUPABASE_ANON_KEY` (publishable-ключ staging).

Чтобы тестировщики входили **без SMS** (бесплатно и без телефона под рукой), на
**staging** задайте секреты edge-функций:

```bash
supabase secrets set --project-ref <staging-ref> \
  TEST_LOGIN_PHONES="+79990000001,+79990000002,+79990000003" \
  TEST_LOGIN_CODE="246810"
supabase functions deploy --project-ref <staging-ref>
```

* Для этих номеров SMS не отправляется, код всегда `TEST_LOGIN_CODE` (ровно 6 цифр —
  столько вмещает поле в приложении). Остальные номера работают как обычно.
* 5 неверных кодов подряд — блок номера на 15 минут (защита от перебора).
* Роль (заказчик/грузчик) выбирается при первом входе номера, как у всех.

### Прод

На проде `TEST_LOGIN_*` **не задавать**, кроме одного номера для проверяющих
Apple/Google (демо-вход для ревью, см. план релиза). Для него — отдельный номер и
код, который не используется больше нигде; после одобрения приложения код сменить.
